# `internal/product`: модель товара и предметные правила

Пакет `product` содержит общую прикладную модель CRUD-сценариев товара и правила допустимости его данных.

## Модель и границы ответственности

`Product` описывает текущее состояние товара: `ID`, `Name`, `Price`, `Version` и `UpdatedAt`. `ID` обозначает устойчивую идентичность товара и не меняется при обновлении. Значимые изменяемые данные — `Name` и `Price`. `Input` содержит эти два поля и используется как входной DTO для создания и замены товара; это не самостоятельная сущность. Раздельные типы не позволяют случайно принять от клиента ID, версию или время обновления как обычные поля ввода.

`Version` — техническая версия сохранённого состояния для контроля конкурентных изменений, а не бизнес-редакция товара.

`UpdatedAt` задаётся при создании и меняется только вместе с именем или ценой. Оно также определяет границу `views_since_update` — просмотров после последнего изменения значимых данных товара в выбранном окне статистики. Запрос с прежними значениями после нормализации имени возвращает текущее состояние без изменения `Version`, `UpdatedAt` и без события `product.updated`. Устаревшая ожидаемая версия всё равно даёт конфликт, даже если переданы текущие имя и цена. Пакет хранит эти метаданные в общей модели, но сам не управляет транзакциями и не выполняет сравнение с сохранённым состоянием.
